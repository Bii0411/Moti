## 제가 정한 것

- **재생 구간 5.65~8.85초, 끝 섞기 0.75초(x17 만):** 이 모션은 몸이 계속 빙글 돌아서, 기본 자세와 섞는 동안 몸 방향이 180°를 넘으면 섞기가 반대쪽으로 한 프레임에 뒤집힘(처음 고른 4.7초 시작에서 목 171° 튐). 처음 섞기 0.8초(25단계 값) 안에 180° 넘김이 없는 5.65초에서 시작하고, 끝 섞기는 25단계 값 1.0초 대신 0.75초로 해야 8.05초의 넘김이 섞기 밖에 남음. 25단계에서 만든 몸짓별 `fadeOut` 칸을 씀. 그래서 처음 오른발 차기는 섞기 안이라 약하게 보임
- **연출 안에서는** 착지 순간(2.6초)에 x16 으로 넘어가서 x17 끝 섞기는 0.5초로 줄여 둠(`firstMeet.kickFadeOut`, 이번 재생만). x16 은 처음부터가 아니라 **이미 몸을 낮춘 1.0초 순간부터** 시작(처음부터면 착지 → 일어섬 → 다시 낮춤으로 출렁임)
- **넓은 구도:** 키 비율 위 1.25·아래 −0.25·너비 1.25(다리를 옆으로 뻗어도 들어오게). 카메라 높이는 360도 그림 수평선(1.43m)에 맞춤(lift 0.33). 처음 0.03 으로 했더니 카메라가 0.9m 로 낮아 360도 바닥 이음매가 띠처럼 보였음. 시연 패널·앨범 다시 보기의 x17 확대도 같은 구도(`camera.byMotion`), 다른 몸짓 구도는 그대로
- **x16 동안 바닥 띠:** 「카메라 따라감 그대로」라 x16 동안 카메라가 머리를 따라 내려가면서 360도 바닥 이음매가 조금 보임(#4·#5). 지시대로 둠. 없애려면 `firstMeet` 에 x16 따라감을 끄는 값을 따로 둘 수 있음
- **카메라 돌기:** −8° → +10°(18°), 돌려차기 + 경계하기 동안(3.6초). 바 1층으로 돌아갈 때 0° 로 돌아옴
- **어두워짐:** 무대 바깥은 검은 층이 0.5초 동안, 무대 안은 0.25초 검은 막 → 그 뒤에서 장소를 바꾸고 0.25초 동안 걷힘(장소가 바뀌는 순간이 안 보이게). 360도 그림을 아직 못 받았으면 검은 막인 채로 최대 2초 기다리고, 넘으면 평평한 그림으로 시작
- **무대가 전체 화면이 되는 방식:** 무대를 그 자리에서 `position: fixed` 로 띄워 앱 화면 크기로 늘리고(빈 자리는 같은 높이로 비워 둠), 끝나면 대화 화면 자리로 되돌림. 확대(17단계)처럼 크기가 바뀌는 동안 3D 그림판도 매 프레임 크기가 바뀜
- **연출이 나오는 때:** 홈 → 서아 → 기본 에피소드 「시작」(아직 오프닝 전, `firstMeet` 없음)일 때만. 대화 목록에서 들어오거나, 시연 패널 「오프닝 다시 보기」는 연출 없이 오프닝. 3D 준비를 1.5초까지 기다리고 넘거나 실패하면 연출 없이 오프닝(이때는 `firstMeet` 을 기록하지 않고 카드도 없음). 모션 파일을 못 받아도 연출 없이 대화로(카드 없음)
- **장소:** 처음 연출은 끝에 대화 장소를 바 1층으로 정함(`setScene(0)`). 특별 에피소드를 먼저 했던 사람도 첫 오프닝이 바 1층에서 나오게. 「다시 보기」는 지금 대화 장소로 돌아감
- **카드:** 끝까지 보거나 건너뛰면 기록(장소 네온 골목, 그때 의상 = 작전복). 「다시 보기」로도 아직 없으면 얻음. 기존 칸 체계를 그대로 쓰려고 몸짓 x17 의 칸으로 만들고 이름만 「첫 만남」, `source` 는 대화(chat), 등급 시크릿. 단계 해금이 아니라서 `only: "firstMeet"` 를 달고 `build_collection` 이 지우지 않게 함. 알림은 다른 시크릿과 같은 카드 알림
- **카드 그림 순간:** 34%(정면을 보며 다리를 높이 찬 순간). 후보 12개 중 얼굴이 보이고 다리가 높은 것. 표정 무표정(neutral)
- **감정 태그:** x17 은 「자신감」(키워드·해금에 안 붙어 대화에서 고를 일은 없음). 따로 둔 x12(Round house Kick 1)도 이름이 「돌려차기」라 같지만 x12 는 불러오지 않음
- **힌트 문장:** 지시문 그대로(마침표 없이)
- 건너뛰기 버튼은 아래 검은 띠 위 오른쪽(아이폰 홈 막대 여백 포함)
- 캡처: 앱 미리보기 창 대신 25단계와 같은 방식(저장소를 잠깐 띄워 헤드리스 Chrome 390px). 연출은 실제 시간으로 찍어 0.5초 간격이 조금씩 어긋남. 확인 스크립트는 저장소 밖 임시 폴더

## 아이폰에서 나중에 볼 것

- **전체 화면 전환:** 무대가 `position: fixed` 로 떠서 화면 전체로 커질 때(0.5초)와 대화 화면으로 줄어들 때(0.8초) 끊기지 않는지. 3D 그림판이 매 프레임 크기를 바꾸므로 17단계 확대보다 큰 범위. 주소창이 접히거나 펼쳐질 때 자리가 어긋나지 않는지
- **검은 띠:** 위아래 띠가 내려오고 걷히는 것(transform 만), 아래 띠·건너뛰기 버튼이 홈 막대에 가리지 않는지
- **카메라 회전:** 넓은 구도에서 서아 주위를 18° 도는 동안 끊김, 360도 바닥이 출렁여 보이지 않는지
- **360도 배경 불러오기 시간:** 네온 골목 그림 1.2MB 를 처음 받는 동안 검은 막이 최대 2초. 받은 뒤 바 1층(0.5MB)으로 넘어갈 때 다시 받는 시간(30-1 부터 떠난 장소 그림을 내려놓음), 그동안 평평한 그림
- 연출 뒤 카드 그림 만들기(네온 골목 360도를 한 번 더 받음)가 오프닝 문단과 겹쳐 버벅이지 않는지

### 2. 온보딩 동안 네온 골목 360도 미리 받기

처음 실행이라 연출이 나올 예정이면(`firstMeet`·오프닝 전) 온보딩 첫 화면이 뜰 때, 3D 준비가 끝나는 대로 `pano_seoa_street.webp` 를 받아 둠(그림만, 구는 연출 때 만듦). 전체 초기화 뒤 온보딩도 같음.

연출 시작 때 검은 막 뒤에서 360도 그림을 기다린 시간(헤드리스 Chrome, 회선을 흉내 냄):

| 경우 | 회선 | 온보딩을 본 시간 | 기다린 시간 |
| --- | --- | --- | --- |
| 미리 받기 있음 | 4Mbps | 5초 | **0ms** (받기 22.3 → 26.9초, 클릭 28.0초) |
| 미리 받기 없음(31단계와 같음) | 4Mbps | — | **2006ms** (최대 2초를 다 기다리고 평평한 그림으로 시작) |
| 미리 받기 있음, 온보딩을 빨리 넘김 | 4Mbps | 1.5초 | 2008ms (아직 받는 중 → 최대 2초 뒤 평평한 그림으로 시작, 받는 대로 구가 나타남) |
| 미리 받기 있음 | 제한 없음(로컬) | 5초 | 0ms (받기 0.19초) |

### 제가 정한 것

- 미리 받기는 3D 준비가 끝난 뒤 시작(그림을 텍스처로 만들 때 3D 그림판 설정을 씀). 그래서 느린 회선에서는 XSTAGE 모션 미리 받기(약 2MB)와 같이 받음
- 미리 받은 그림은 연출 전까지 메모리에 남음(그리지 않아 GPU 에는 아직 안 올라감). 온보딩 뒤 연출을 안 보면(특별 에피소드부터 등) 서아가 네온 골목에 갈 때까지 남아 있음. 30-1 의 「한 장만」 규칙에서 이 한 장만 예외
- 기다리는 최대 시간은 31단계 그대로 2초(`firstMeet.panoWaitMs`)
- 따라감을 끄는 것은 연출 동안만. 연출을 시작할 때 끄고, 끝나거나 건너뛰거나 시연 패널에서 멈출 때 다시 켬

### 아이폰에서 나중에 볼 것

- 온보딩 화면에서 360도 그림(1.2MB)과 모션 파일을 같이 받는 동안 온보딩 3D·버튼이 버벅이지 않는지
