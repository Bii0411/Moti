# 81. 부재중 셀카 중복 전송 방지

서아가 부재중 셀카를 한 장 보낸 뒤에는, 유저가 다시 실제로 대화하기 전까지 그 이야기 줄기에서 셀카를 더 보내지 않음. 셀카를 끼워 넣을 때 대화 기록이 60줄로 잘리던 문제도 고침.

브랜치: `step/81-away-selfie` · 서버 수정·유료 API 호출 없음 · 셀카 구도·모션·대사·알림 디자인, 10분·2단계 이상 조건, 카메라·컬렉션, 팀원 [91] 작업은 건드리지 않음.

## 상태 저장 키와 초기값

`S.sp`(기존 저장 묶음) 안에:

| 키 | 모양 | 뜻 |
| --- | --- | --- |
| `can` | `{ main: true, s2: false, … }` | **새 키.** 줄기마다 부재중 셀카를 보낼 수 있는지. 실제 대화 → `true`, 셀카 예약 → `false` |
| `leave` | `{ 줄기: {at, done, demo} }` | 기존 그대로. 떠난 시각(이제 이미 있으면 덮어쓰지 않음). 대화방에 다시 들어오면 지움(= 10분 전이면 취소) |
| `pend` | `[{type:"away", th, pid, …}]` | 기존 그대로. 그림을 만들 예약 사진(줄기 `th` 가 붙음) |
| `notes` | `{ 줄기: [줄…] }` | 기존 그대로. 서버에 붙일 사진 줄 |

**초기값(`can` 이 없는 줄기 — 예전 저장값·처음 들어가는 줄기·초기화 뒤):** 앱을 열 때(`init`) 본편·지금 줄기·`S.threads` 의 줄기마다 한 번 정해 저장. 다른 줄기는 처음 필요할 때 같은 규칙으로.
1. 그 줄기 대화 기록에서 마지막 **실제 유저 대화**(`r:"u"`, 선물 `gift`·`srv`, 포즈 부탁 `poseAsk` 줄 제외)를 찾음. 없으면 → `false`
2. 그 뒤(순서상 뒤 또는 시각이 같거나 뒤)에 부재중 사진 말풍선(`r:"ph"`, `away`)이 있으면 → `false`
3. 그 줄기의 예약 사진(`pend`)이 있으면 → `false`
4. `leave[줄기].done`(이번 떠남에 이미 받음)이면 → `false`
5. 그 밖 → `true`

## 재활성화 조건

**`can=true` 가 되는 때는 한 곳뿐:** `send()` 에서 서아 대화방(`room==="seoa"`)의 텍스트 내 말이 ① 빈 말·답장 기다리는 중 아님 ② 실패해 잠긴 줄기 아님 ③ 밤 넘기기 관문(`Night.gate()`) 통과 를 지나 대화 기록에 들어간 바로 뒤. 그때의 줄기(`Thread.cur()`)만.

다음으로는 바뀌지 않음(그대로 둠):
- 대화방 입장·재입장, 홈·앨범·다른 대화방, 앱 종료·새로고침·백그라운드
- 다시 들어올 때 인사(`Greet`)·시스템 줄·「[다음 밤]」(밤 넘기기는 `send()` 를 거치지 않음)
- 선물·순간 선물(`send(…, {gift, srv})`), 포즈 부탁(`Pose.ask` → `poseId`), 카메라
- 되감기(대화 기록만 그 시점으로, `can` 은 그대로)

**`can=false` 가 되는 때:** 부재중 셀카를 예약(`arrive`: 말풍선 자리를 넣는 순간, 그림을 만들기 전). 그림 만들기가 실패해도 `false` 그대로 → 다음 실제 대화 전까지 새 예약 없음.

**떠남 타이머:** `markLeave` 는 ① 이미 `leave[줄기]` 가 있으면(세는 중이거나 이번에 받음) 아무것도 안 함 ② `can=false` 면 안 셈. 10분 전에 대화방에 돌아오면 `enter()` 가 그 줄기의 `leave` 만 지움 → 다시 나가면 새로 10분.

**이번 단계는 캡처하지 못함.** 이 작업 환경에서 미리보기 서버 칸 5개가 다른 대화의 서버로 차 있었고(새로 띄우기 거절), 직접 로컬 서버를 띄우는 명령은 권한에서 막힘. 그래서 화면 대신 위 로직 스크립트로 확인함. 화면 모양(말풍선·배너·앨범)은 이번 단계에서 바꾸지 않았음. 병합 뒤 390px 로 한 번 보면 좋은 것: 실제 대화 → 홈 → 시연 「10분 지난 뒤 셀카 받기」 → 배너·사진 말풍선 → 다시 시연 없이 재입장·퇴장 반복해도 새 말풍선 없음.

## 제가 정한 것

- **저장 키 이름 `S.sp.can`**(줄기 → true/false). 떠난 시각·예약 사진은 기존 `leave`·`pend` 를 그대로 씀(이미 줄기마다 나뉘어 있어서 새로 만들지 않음).
- **「실제 대화」 판정:** `send()` 의 `o`(선물·순간 선물·밤 요청 옵션)가 없고 포즈 부탁(`poseId`)이 아닐 때. 「다시 보내기」(91 예비 지문 재전송)는 유저가 쓴 말을 다시 보내는 것이라 실제 대화로 셈. 다른 캐릭터 대화방 말은 서아 셀카와 상관없음.
- **포즈 부탁 내 말 줄에 `poseAsk:1` 표시를 새로 남김** — 예전 저장값을 읽을 때(초기값) 포즈 부탁 줄을 실제 대화로 세지 않으려고. 화면·서버 기록에는 영향 없음(그리지 않는 값).
- **처음 상태가 확실하지 않으면 `false`**: 실제 대화가 하나도 없는 줄기(새 유저·처음 들어간 크리스마스·초기화 뒤)는 첫 말을 할 때까지 셀카 없음. 처음 셀카도 「말을 건 뒤 떠나면」이 되는 셈.
- **시연 「10분 지난 뒤 셀카 받기」는 can 과 상관없이 보냄**(기존 동작). 다만 시연으로 받은 것도 받은 것이라 받은 뒤 `can=false` 가 됨 → 일반 셀카는 다음 실제 대화 뒤. 시연은 몇 번이든 다시 누를 수 있음.
- **사진 그림을 만드는 중 줄기를 바꿔도 그림은 끝까지 만들어 저장**하고, 말풍선 자리는 예약한 줄기의 기록(`S.threads[줄기].chat`)에서만 찾아 채움. 그림을 버리지 않은 이유: 이미 그 줄기 기록에 「받은 시각」 자리가 들어가 있어서.
- **상태를 지우는 초기화:** 전체 초기화(저장값 통째), 되감기 「처음부터」(그 줄기), 시연 「에피소드 처음부터」(그 에피소드), 시연 「서아 초기화」(지금 줄기). 시연 「대화 초기화」(`RESET.chat`, 모든 대화 기록만 지움)는 지시에 없어 그대로 둠 — 이때 `can` 은 이전 값이 남음.
- **되감기**는 `can` 을 바꾸지 않음(지시대로). 되감기로 셀카 전 시점으로 돌아가도 `false` 면 다음 실제 대화까지 기다림.
- **확인 스크립트를 `tools/test_away_selfie.mjs` 로 저장소에 넣음** — 팀원이 같은 확인을 다시 돌릴 수 있게. 테스트 안에서만 사진 만들기 함수를 바꿔 끼움(제품 코드는 그대로).
- 커밋 나눔: A(전송 제한 핵심 + `send()` 연결)에 줄기별 `can`·초기값 계산도 같이 들어감(같은 함수라 떼면 A 혼자 동작하지 않음). B 커밋은 초기화 연결(처음부터·에피소드 처음부터·서아 초기화). 둘 다 같은 브랜치에 차례로.

## 아이폰에서 나중에 볼 것

시각 효과(블러·그림자·애니메이션·3D)는 바꾸지 않음. 다만 떠남을 세는 방식이 브라우저 사건에 기대므로:
- 사파리에서 대화방에 있다가 **홈 화면으로 나감 / 탭 바꿈 / 화면 잠금** → 10분 넘게 뒤 돌아왔을 때 한 장만 오는지(`visibilitychange`·`pagehide` 가 둘 다 와도 첫 시각 유지).
- 사파리가 백그라운드 탭을 **새로 불러온 경우**(메모리 정리) 돌아와서 중복으로 오지 않는지.
- 홈 화면에 추가한(PWA) 상태에서 앱 전환 뒤 같은 확인.
