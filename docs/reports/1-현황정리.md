## main과 v2 차이 요약

- v2는 **예전 앱(`app.js`·`style.css`)** 을 고쳤다. 그 사이 main은 **새 앱을 `index.html` 한 파일**로 다시 만들었고 예전 앱은 `v1.html`이 됐다.
- 그대로 병합하면 `app.js`·`style.css`에서 git 충돌이 나고, 풀어도 v2 기능은 `v1.html`에만 들어간다. 지금 앱에는 들어가지 않는다.
- 충돌 없이 그대로 쓸 수 있는 것은 `motion.js`(서아 전용 c01~c05, 대기 m25)뿐이다.
- 배포 서버에는 `/judge`가 없어 **서버 v2는 아직 배포 전**으로 보인다. 서버 v2가 배포되면 `/chat` 응답이 `reply` → `dialogue`로 바뀌어, 지금 `index.html`은 서버 답을 못 쓰고 예시 대사로만 대답하게 된다.

| 항목 | main | v2 |
| --- | --- | --- |
| 대화 표시 | `*…*`를 쪼개 지문/말풍선 | `action`·`dialogue` 필드를 받아 행동 한 줄/말풍선 |
| 카메라 | `71d2072`에서 조정됨 | 안 바꿈 → main 유지 |
| 서아 인트로 | 짧은 한 줄, 인트로 화면 없음 | 서버 `OPENING` 긴 원고 + 문단별 몸짓 |
| 감정·표정 | 있음 (`FACE`, `EMO2FACE`) | 감정 저장만, 표정 없음 |
| 판정 대기 | 없음 (대화 횟수로 5단계) | `/judge` 뒤에서, 다음 전송은 판정 뒤로 |
| 해금 연출 | 없음 (선물로 배운 모습) | 해금 지도 → 몸짓 재생 → 토스트 → 기록 |

## 제가 정한 것

1. **v2는 병합하지 않고 기능별로 다시 만드는 것을 추천**했다. 이유: v2가 고친 파일은 지금 앱이 쓰지 않는 `v1.html` 쪽이라, 병합해도 지금 앱엔 효과가 없다.
2. `motion.js`는 main이 갈라진 뒤 바꾸지 않았고, c01~c05가 새 VRoid 모델 기준으로 맞춰져 있어 **그대로 가져올 것**으로 분류했다.
3. 카메라는 **main 값 유지**로 정했다 (v2는 카메라를 안 바꿈).
4. 행동(`action`)은 v2의 기울임 한 줄(`.actn`) 대신 **새 앱의 지문(`.mnarr`) 모양**으로 그리자고 적었다. 화면에 지문 모양이 두 가지가 되지 않게.
5. 해금 지도·장소·인트로 원고·감정→표정 대응표는 CLAUDE.md 규칙에 따라 **JSON으로 분리**하는 것으로 적었다. 원본은 서버 `yoon_seoa_prompt.md`.
6. 다음 두 가지는 기획 결정이 필요해 표에 "결정 필요"로만 남겼다:
   - 인트로를 별도 화면으로 보여 줄지, 대화방 안에서 보여 줄지
   - 해금 기록(`S.firsts`)을 추억 앨범(지금은 선물 반응 16칸)과 합칠지
7. main의 관계 5단계(대화 횟수)는 v2의 6단계(판정)로 **바꾸는 것**으로 적었다. [plan.md](../plan.md)의 관계 진행이 6단계이기 때문.
8. 서버 배포 상태는 `/openapi.json`에 `/judge`가 없는 것으로 "v2 미배포"라고 판단했다. Render 대시보드는 볼 수 없어 확인하지 못했다.
9. 차이 표가 길어 보고서에는 요약만 두고, 전체 표는 별도 문서 `docs/v2-diff.md`로 만들었다 (지시문에 없던 파일).
10. 저장소에 `.gitignore`가 없다. 이번 단계는 문서만이라 만들지 않고 status.md 남은 일에 적었다.
11. 출처 표의 three.js·Noto Sans KR 라이선스(MIT, OFL)는 공개된 일반 정보로 적었다. 나머지 그림·모델은 저장소에서 출처를 알 수 없어 "확인 필요"로 두었다.
