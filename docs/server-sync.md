## 80 · S4 통합 (서버 S4 · S4-1 · S4-1-1) — 지금 규칙

이 절이 지금 본편 규칙이다. 아래 51 절의 「엔딩 신호(departed)」·「남은 날」·「5단계에 오른 뒤 되감기 지점」은 예전 출발 구조이고 지금은 쓰지 않는다. 자세한 것은 [80 보고서](reports/80-S4-통합연동.md).

- **본편 단계 이름:** 경계 → 티키타카 → 썸 → 고백 직전 → **위기** → 연인. 화면의 지금 단계 이름은 `state.stage_label` 그대로(엇갈림 중이면 「엇갈림」). 크리스마스 에피소드의 5단계 이름은 「엇갈림」 그대로(`data/episodes.json` s2 `stage.stageNames`).
- **state 는 받은 그대로:** 본편 `/judge` 응답 state 를 통째로 저장해 다음 본편 `/chat`·`/judge` 에 보냄. 앱이 만들거나 고치는 키는 `route`(아래) 하나뿐(시연 패널 제외). 크리스마스 요청에서는 본편 전용 키(`crisis`…`night_wait`·`scene_msgs`·`rift_sorry`·`route`·`scene`·`scene_judges_left`·`used_events`·기억 키 4개·이름 흐름 키)를 빼고 `pending_event` 는 null.
- **갈래:** 2단계 · route null · (`night_next` == `NIGHT_START_2` 또는 `used_events.NIGHT_END_2`) 인 판정을 받으면 다음 요청 전에 앱 집계로 정함(장난 > 다정 → tease, 그 밖 care). 예전 조건(호감 40·outside)이 먼저면 그때. 서버가 정한 route 는 그대로.
- **pending_event:** 그 사건을 실어 보낸 /chat 이 정상 답장(HTTP 200, 「…」 아님)을 보여 준 뒤에만 비움. 실패면 그대로 두고 「다시 보내기」로 같은 사건을 다시.
- **/judge:** `judgeEvery` 3, `judge_soon` 이면 답장마다. `reply_ok` = last_user 메시지와 같은 개수의 true(묶음에는 정상 답장만 들어감, 예전 묶음은 생략). last_user 1000자를 넘으면 오래된 메시지를 통째로 뺌(reply_ok 도 같이). `recent` = need_summary 또는 stage_note_due·stage_note_queue 가 있을 때 실제 대화 최근 80개(실패 답장과 그 요청 제외).
- **밤 넘기기:** `night_next` + pending `NIGHT_END`/`RIFT_START` → 그 마무리 답장 → 유저 한 번 답의 정상 답장 → 남은 판정 묶음 판정 → 시간 카드(`night_card`) → `/chat` message 「[다음 밤]」(말풍선·기록 없음) → 바로 `/judge`(last_user 「[다음 밤]」, last_reply 첫마디, need_summary false, reply_ok []). 「[다음 밤]」은 한 번만(실패 재시도는 같은 요청).
- **되감기:** 지점 = 5단계 + pending `CRISIS` 가 정해진 판정 직후(위기 소식 답장 전, state 통째). `rewind_offer` true → 「그 밤으로 돌아가 볼까요?」 [되감기] [이대로 갈게요] 한 번. 되감으면 그 state 를 통째로 보냄.
- **순간 선물 4단계:** `gift_moments` 의 flower 이름은 「바 여분 열쇠」(id 그대로).
- **판정 flag `withdraw`:** 앱은 쓰지 않음(해금·갈래·연출 없음).

## 42 · state 신호 (`/chat`, `/judge`)

크리스마스 에피소드(s2) 안에서 메시지를 보낼 때 state 에 더하는 값. 에피소드 밖(본 이야기·다른 에피소드)에서는 보내지 않는다.

| 키 | 값 | 설명 |
| --- | --- | --- |
| `episode` | `"s2"` | 크리스마스 이브 정전 |
| `episode_stage` | `1` ~ `6` | 에피소드만의 관계 단계(본 이야기 단계와 따로) |
| `episode_stage_name` | `"경계"` `"티키타카"` `"썸"` `"고백 직전"` `"엇갈림"` `"연인"` | 앱 이름(아래 「물어볼 것」 1) |
| `location` | `"크리스마스 거리"` 또는 `"서아의 자취방"` | 에피소드 안 장소는 이 둘뿐 |

- `/chat` 의 `stage`·`affection` 은 **본 이야기 값 그대로** 보낸다(서버가 에피소드를 모를 때 지금처럼 동작하게).
- `/judge` 에는 `stage`·`affection`·`stage_flags` 를 **에피소드 값**으로 보낸다. 앱은 돌아온 `state.affection` 과 보낸 호감의 차이(호감 변화)와 `flags` 만 에피소드에 더하고, 서버가 바꾼 단계·사건(`pending_event`)·출발 일수는 쓰지 않는다. 에피소드 단계는 앱이 정한다:
  - 기준 호감 `[0, 8, 18, 30, 42, 55]`, 단계마다 상한(다음 기준 − 1), 한 번에 한 단계만
  - 5 → 6 은 판정 플래그 `sincere` · `pursue` · `comfort` 중 하나가 있어야 함
  - 값은 앱 `data/episodes.json` s2 `stage`

## 49 · 선물 줄 — 처리함

- 49 · 선물에서 미리 정한 반응을 뺐다. 선물 줄 형식 "[유저가 선물함: {이름}]". 서아가 지금 장면에 맞게 받도록(다투는 중이면 다투는 채로, 다친 밤이면 고맙게), 서아 취향이나 기분에 맞는 선물은 판정에서 care 로 크게 치도록 프롬프트에 한두 줄.
- 앱이 보내는 것: 대화방 ＋ 「선물」로 선물을 주면 화면에는 내 행동 「(커피를 건넨다)」, `/chat` 의 `message` 와 기록(`history`)·`/judge` 의 `last_user` 에는 `[유저가 선물함: 커피]` 가 간다. 선물 이름은 커피·라멘·꽃다발·반지(`data/gifts.json`). 몸짓은 서버가 고른 것을 그대로 쓴다(앱이 정한 반응·등급 뽑기 없음).
- 서버 답이 없을 때 앱은 서아 지문 한 줄 「*서아가 말없이 받아 든다.*」만 넣는다.
- 2026-11-25 서버 v2 로 4종을 보내 본 결과: 네 번 모두 장면에 맞는 지문·대사와 몸짓(m20·m01·c02·m03)이 옴. 프롬프트 줄은 아직 없는 상태.

## 50 · 순간 선물 (50-1 에서 단계별 하나씩으로 고침)

선물이 두 종류다(`data/gifts.json`).

- **언제든 선물:** 사탕 · 초콜릿 · 물 한 잔 · 반창고 · 손난로. 처음부터 줄 수 있다. 받는 몸짓은 앱이 고정한다(서버가 준 `motion_id` 보다 우선).
- **순간 선물:** 관계 단계 하나에 하나, 여섯 개. 평소엔 잠겨 있고, 서버가 「지금이 그 순간」이라고 알려 줄 때만 열린다(열린 뒤 유저 메시지 3번 안에 주지 않으면 닫힘, 한 번에 하나).
- 커피 · 라멘은 목록에서 빠졌다(49의 선물 이름 목록 대신 이 목록).

| --- | --- | --- |
| 1 경계 | 구급상자 (`firstaid`) | 서아가 다쳐서 왔을 때 |
| 2 티키타카 | 칵테일 (`cocktail`) | 서아가 지쳐 보이거나 자기 술 얘기를 할 때 |
| 3 썸 | 따뜻한 수건 (`towel`) | 비에 흠뻑 젖어 왔을 때 |
| 4 고백 직전 | 꽃다발 (`flower`) → 80 부터 「바 여분 열쇠」(id 그대로) | 처음 이름을 불렀을 때, 마음을 전할 순간 |
| 5 엇갈림 | 우산 (`umbrella`) | 빗속에서 떠나려는 서아를 붙잡을 때 |
| 6 연인 | 반지 (`ring`) | 남기로 한 뒤, 결정적인 순간 |

단계가 지나도 앞 단계 선물은 계속 열릴 수 있다(예: 4단계에서도 구급상자·칵테일·따뜻한 수건·꽃다발).

### 앱이 보내는 것 — `/chat` `state.gift_moments`

지금 열 수 있는 순간 선물 목록. **앱이 이미 거른 것만 온다:** ① 본 이야기 관계 단계 ≥ 그 선물의 단계 ② 그 선물의 반응 모션이 앱에 있음 ③ 지금 열린 순간이 없음. 특별 에피소드 중에는 늘 `[]`. 서버는 단계를 다시 따질 필요 없이 이 목록 안에서만 고르면 된다.

```json
"gift_moments": [
  { "id": "firstaid", "name": "구급상자", "when": "서아가 다쳐서 왔을 때" },
  { "id": "cocktail", "name": "칵테일", "when": "서아가 지쳐 보이거나 자기 술 얘기를 할 때" }
]
```

지금(2026-11-25)은 반응 모션이 하나도 없어 목록이 늘 빈 상태다 — 모션이 들어오면 그 선물부터 목록에 나온다.

### 서버가 할 것 — 답장 JSON `gift_moment` — 아직

- 대화가 목록 중 어떤 선물의 `when` 에 맞는 장면이면, 답장 JSON 에 넣는다:

```json
"gift_moment": { "id": "cocktail", "reason": "서아가 지쳐 보여요" }
```

  - `id` 는 그 턴에 받은 `gift_moments` 안의 id 만.
  - `reason` 은 서아 상태를 짧게(15자 안팎). 앱 선물 창 맨 위 칸에 그대로 보인다.
- 맞는 장면이 아니면 넣지 않는다(필드를 빼거나 `null`). **자주 넣지 않는다.** 같은 선물은 한 번 연 뒤 **최소 10턴** 은 다시 넣지 않는다.
- 서버가 `gift_moment` 를 한 번이라도 보내면 앱의 임시 규칙(서아 답장의 말로 구급상자·칵테일·따뜻한 수건을 여는 규칙)은 그 기기에서 꺼진다.

### 선물 줄 (49 형식에 덧붙임) — 처리함

`[유저가 선물함: {이름}]` 뒤에 ` · ` 로 이어 붙는다(순서 그대로):

| 붙는 말 | 언제 | 판정 |
| --- | --- | --- |
| `순간 선물` | 열린 순간 선물을 줌 | **care 크게** |
| `서아 기분에 맞는 선물` | 지금 서아 기분에 맞는 선물 | **care 크게** |
| `또` | 직전 3번 안에 같은 언제든 선물을 또 줌 | 작게(앱도 이 턴이 든 판정의 호감 상승을 절반으로 줄임) |

예: `[유저가 선물함: 칵테일] · 순간 선물`, `[유저가 선물함: 물 한 잔] · 서아 기분에 맞는 선물`, `[유저가 선물함: 사탕] · 또`

- **몸짓은 앱이 정한다.** 선물 턴에 서버가 준 `motion_id` 는 쓰지 않는다. 언제든 선물 = 선물마다 정한 몸짓, 또 = 한숨·팔짱, 순간 선물 = **선물마다 반응 모션 하나**(어느 단계에서 줘도 같은 몸짓).
- **반응 대사는 서버가 쓴다:** 같은 선물이라도 **관계 단계마다 다르게**, 짧게(1~2문장), 지금 장면에 맞게(49 그대로). 예: 같은 칵테일이라도 티키타카에서 받을 때와 연인일 때의 말이 달라야 한다.

### 엔딩 신호 (지금 서버 그대로 — engine.py `1905866` 기준 확인)

- 앱이 보는 것: `/judge` 응답 `state.ending == "departed"`. 서버는 5단계에서 `time_advance` 로 `departure_days_left` 가 0 이 되고 `pursue` 가 없으면(`_next_stage` 의 5→6 이 안 됨) `_apply` 끝에서 `ending = "departed"` 를 넣는다.

## 54 · 조연 · 성공 엔딩

원고: [drafts/조연-성공엔딩-원고.md](drafts/조연-성공엔딩-원고.md)(새로 들어옴), [drafts/51-갈래-되감기-원고.md](drafts/51-갈래-되감기-원고.md)(사흘 판으로 바뀜). 대사·지문은 원고 그대로.

### 출발은 「사흘 뒤」

- 5단계 떠난다는 말(DEPARTURE)의 출발을 7일 → **사흘 뒤**로. `departure_days_left` 시작값 3.
- 하루가 지날 때마다 남은 날 지문 한 줄(51 원고 「남은 날 지문」): 2 → *서아가 떠나기까지, 이틀.* / 1 → *서아가 떠나기까지, 하루.* / 0 직전 → *오늘 밤이 지나면, 서아는 떠난다.*
- 앱 실패 에필로그 첫 줄은 이미 「사흘째 밤…」으로 바꿨다(`data/rewind.json`). 앱 시연 패널의 「본편 실패」도 `departure_days_left` 3 을 넣는다.

### 조연 — 갈래마다 한 명, 한 걸음씩 (원고 1~3번)

- 장난 갈래(`route` = `tease`) = **마리**, 다정 갈래(`care`) = **태오**.
- 조연마다 나온 횟수를 세어 **처음 → 두 번째 → 마무리** 순서로 하나씩. 같은 장면을 되풀이하지 않는다. 단계가 안 맞으면 건너뛰지 않고 기다린다.
- 갈래가 정해지기 전(1~2단계)은 지금처럼 단계 목록에서 고르고, 정해진 뒤엔 그 갈래 조연을 **두 배 자주(2:1)**.
- 다른 갈래의 조연은 한 번씩만: 다정 갈래의 마리 = 3단계 「처음」 하나, 장난 갈래의 태오 = 1~2단계 「처음」 + 5단계 의뢰 한 줄.
- 태오는 5단계 의뢰를 **가져온 사람**. DEPARTURE 때 두 갈래 모두 한 줄: 「태오가 가져온 일이야. …큰 거.」
- 마무리는 6단계 첫 아침 뒤, 성공 엔딩 전에 그 갈래 조연만 한 번.

### 성공 신호 — `state.ending = "stayed"` (새로 필요)

- 6단계 첫 아침 장면 **+ 그 갈래 조연 마무리**가 나온 뒤(또는 6단계에서 유저 메시지 **15번**이 되면), `/judge` 응답에 `state.ending = "stayed"` 를 **한 번** 넣어 주세요. `route` 도 같이 있으면 앱이 그 갈래 에필로그를 고른다(없으면 앱이 다정 갈래로 봄).
- 앱이 받으면: 원고 4번 갈래별 에필로그(장난 = 카운터 안쪽, 다정 = 옥상의 비)를 지문·대사로 보여 주고 → 끝 화면 한 번(「서아가 남았어요」·「계속 대화하기」) → 엔딩 기록 「남은 밤 · …」.
- **대화는 잠그지 않는다.** 「계속 대화하기」를 누르면 끝 화면만 닫히고 6단계 그대로 `/chat` 이 이어진다(원고 6번 연인 일상). 앱은 한 번 본 성공 엔딩을 다시 띄우지 않으니, 서버가 그 뒤에도 `stayed` 를 계속 보내도 괜찮다.
- 연인 일상: 6단계 사건 목록에서 마리·태오 마무리는 빼 주세요(이미 씀). 「사장님」 호칭 그대로, 둘만 있을 때 가끔 유저가 말한 이름.

### 시연 패널이 보는 `/judge` 값 (있으면 표시, 없으면 숨김)

- `affection_delta`, `flags`, `reason`, `changes`, `progress.talk_bonus`, `progress.stage_bonus` / `stage_bonus_max`, `progress.stage_user_msgs`, `progress.min_msgs`, `progress.min_msgs_left`. 지금 안 보내는 값이 있어도 앱은 그 줄만 숨긴다.
